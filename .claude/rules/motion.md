# Motion, loading and toasts

<!-- Moved word for word from `.claude/rules/design-system.md` on 2026-11-09, to keep that file under the 40k limit `__tests__/docs-canary.test.ts` enforces. Its paths are as broad as the design system's, so a component edit loads the same text as before: this split keeps each file under the limit, it does not load less. -->

- **Motion system** (motion pass, 2026-09-16, `docs/plans/motion-pass.md`) — a duration ladder named by ROLE (`--duration-press` 100 / `-fast` 150 / `-sheet` 180 / `-normal` 250 / `-slow` 400) and five recipes in `globals.css`; reach for one before writing a keyframe. **Appear** `.motion-fade` (opacity only — content arriving into a surface already on screen does not rise; key the element so a swap replays it). **Open** `<Collapse open>` (`components/primitives/Collapse.tsx`, grid rows 0fr→1fr) — closed is still ABSENT from the DOM, so it replaces `{open && …}` without changing what "collapsed" means; pass `spaceAbove` when the parent spaces it with `space-y`, or the margin outlives the close and snaps on unmount. **Turn** `.motion-chevron` — one `expand_more` rotated, never a glyph swap (`design-canary` fails the build on `? 'expand_less' : 'expand_more'`). **Press** — cards 0.98, chips 0.97, icon buttons 0.94, text dims to 0.6, list rows flash `--press-bg` (8% dark / 6% light — its own token, because the resting surface tint it first borrowed was invisible under a finger in light mode); an inline `background` outranks `:active`, so a pressable row needs its background on a class. **Fill** — a bar travels to a new value on change only. **Refresh in place** `.motion-busy` + `aria-busy` — old content stays, dimmed to 0.6, while the new loads (opacity only, survives reduced motion); the way to show a refetch without a skeleton. **Page open** `.pane-page-open` — a foldable's right page taking a new page: in from the fold (a `--space-5` glide under a fade, `--duration-normal`), only ever rendered in two-page mode; reduced motion keeps the fade (`docs/plans/foldable-layout.md`).
  - **Loading: a skeleton holds every card's place, and a screen fills top to bottom** (loading cascade, `docs/plans/loading-cascade.md`). While a card loads, its place is a skeleton the SIZE OF THE CARD — never nothing (`return null`, so it pops in later and shoves the screen) and never a "Loading…" line. On a screen of independently-fetching cards, wrap each in `<RevealSlot>` inside a `<RevealGroup>` (`components/primitives/Reveal.tsx`). **A slot holding its skeleton never holds anything up** — its box is already the card's size, so filling it moves nothing. Only a SPACE-LESS slot (`placeholder={null}`, a card that is usually absent) holds the cards below it, and only for `SPACELESS_WAIT_MS` (300ms); past that they show, and a late card that does exist nudges them — rare, and the price of not waiting. The first cut made every card wait for every card above it, and Stats sat behind the AI greeting's live model call with its other data already in hand (Grant, on his phone, 2026-10-06: "a little slow"). So: a card that ALWAYS renders something gets a measured placeholder, never `null` — the admin inbox was space-less and held the payments list for no reason. The card stays MOUNTED behind its skeleton, so a card that fetches inside itself reports with `useRevealReady(ready, empty)` (inside a slot it MAY return null while loading — the slot holds the place); data the parent owns goes in the slot's `ready` prop. With `canBeEmpty`, a card that is ready and renders nothing closes its slot (read off the DOM — no card restates its own empty conditions); `placeholder={null}` is for a card that is usually absent: it takes no space but still holds its ORDER for that brief wait. Ready within 100ms of the screen mounting shows with no fade; later batches stagger 40ms. A lazy tab's chunk fallback is a copy of that tab's own first loading frame, in `components/TabFallbacks.tsx` — never another tab's skeleton. `__tests__/loading-canary.test.ts` enforces the common shapes (null-while-loading, "Loading…" text and copy). It began as a ratchet over the offenders of the day; phase 5 emptied it (2026-10-05), so it is strict — a new offender fails with nowhere to list it. Its one exemption is an OVERLAY (the fixed anomaly toast stack holds no place, so nothing-while-loading is correct), and the exemption must keep matching or it fails as stale. It is a source heuristic and misses other shapes — the rule here is the contract. A slot's readiness must mean an ANSWER, not `!loading`: hooks report "not loading" before their input (the active name) has resolved, which is how the greeting once let the whole Stats register through.
  - **A refetch keeps its content; only the first load shows a skeleton.** Home, Next session, Payments, Birds and Ledger (and the retired Sign-Ups tab) used to flip `loading` on every refetch, so a sign-up or a cover blinked the surface back to a skeleton before showing what changed; so did RosterPage and ReleasesView after every save, and `useCheckIn` after a check-in (all fixed in the loading cascade). Inside a `RevealSlot` the primitive enforces it — a revealed slot never returns to its placeholder; outside one the guard is a `loadedRef` (or simply never setting `loading` after the first load). A refetch that FAILS still sets `loadError`, which replaces the stale content — keeping old data is never allowed to stand in for a failure.
  - **Reduced motion keeps the fade.** The wildcard rule zeroes every animation, and `.motion-fade`, `.field-error` and `p[role="alert"]` are given back under `!important` — an error arriving is comprehension, not movement. Canary-pinned.
  - **Frequency decides.** The tab switch and the Stats registers crossfade (opacity, 150ms) because they are the most-seen transitions in the app; `.status-celebrate` is spent only on rare, consequential moments (check-in saved, session created, club created).
  - **Burst** — the sign-up celebration has its own rule, `.claude/rules/shuttle-burst.md`, which loads with its files. The lesson from it that holds for ANY animation: never run one inside a View Transition morph — Safari paints a transition from STATIC snapshots, so it is invisible on iPhone; start it from `withViewTransition`'s `onFinished`, and verify a transition change in Playwright's WebKit too, not Chromium alone.
- **Toasts** (`.toast` / `.toast-stack`, added with the admin notice rework): transient notices that float over the page instead of occupying a card in it. **The stack is `pointer-events: none` and each `.toast` re-enables it** — without that, a fixed overlay spanning the content column swallows taps on whatever is beneath, including the primary action of the card it floats above. `z-index: 55` is deliberate: above `.rail-bar` (50) so a toast is never behind the nav, below `.bottom-sheet` (60) so an open sheet always wins. Severity is a tinted left edge plus the icon, never a flooded surface — full amber at this size reads as a button and red as a failure that already happened. **The top toast (`TopToast`, mounted once in `HomeShell`) is reachable from anywhere through `showTopToast()` in `lib/topToast.ts`** (2026-10-20): a window event, no store, with `useTopToastBus()` in the shell as the one listener that owns the timer. A MOMENT raised by a card deep in the tree — the advance form's "Session created!" — goes there, never into a `StatusBanner` parked in the card; `__tests__/top-toast-bus.test.tsx` holds the contract.
- **Loading skeletons**: `components/primitives/CardSkeleton.tsx` — `CardSkeleton` (one card), `TabSkeleton` (HOME's body only: tiles, the server-rendered announcement or no slot, the sign-up card), `AdminTabSkeleton` (the console's first three cards). A loading frame and the screen it hands over to read ONE set of heights — `CONSOLE_HEIGHTS` (here, read by `CommandCenter`) and `STATS_HEIGHTS` (`components/TabFallbacks.tsx`, read by `SkillsTab`) — because two copies drifted: the Stats chunk fallback was written before the register became a RevealGroup and moved the page when the chunk arrived. Each other tab's loading frame is in `TabFallbacks.tsx`. Every height is MEASURED from the running app (comment says when and at what width) — a guessed height is a jump. How they are ordered and revealed is the "Loading" rule under Motion system, above. Replaced the full-page `ShuttleLoader` on Home and the (since retired) Sign-Ups tab.
