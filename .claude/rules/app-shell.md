# The app shell: tabs, launch screen, keep-alive

<!-- Moved word for word from the root CLAUDE.md "Gotchas" on 2026-11-09, to keep the always-loaded file short. -->

- **4 tabs**: Home, **Stringing**, **Stats**, Profile. **Sign-Ups left the nav on 2026-09-16**: Home's sign-up card is the list now (`components/home/WhoElseIsIn.tsx` opens the numbered roster with the waitlist and per-name kudos; cancelling lives on the card as `HomeTab.handleCancel`), and `components/StringingTab.tsx` took the slot. `toTab()` in `HomeShell` maps the retired `players` id to Home, because a shared `?tab=players` link, an older push and a PWA's restored last tab all still carry it. Admin reachable via Profile → "Admin tools →" or `?tab=admin` deep link. (Tab id is still `'skills'` for backcompat; the `nav.skills` i18n key renders "Stats" / "数据".) Everyone sees the same `<StatsV2Shell />` — see the Stats Tab section above. `SkillsTab` no longer takes an `isAdmin` prop: the admin-only radar arrangement (and the `SHOW_ADD_PLAYER_FORM` / `SHOW_SKILLS_OVERLAY` constants that had gated it off since v1.3) went with the Stage 8 removal.
- **Cold-start splash = the launch screen** (`docs/plans/launch-screen.md`, 2026-10-03). `<LaunchScreen>` in `app/layout.tsx` is server-rendered, so before any JS the app icon's shot loops as CSS keyframes, generated from `lib/launchMotion.ts` (the same model the post-hydration frames use). After hydration it reads the SERVER-RENDERED page. `[data-signed-out-welcome]` → the shot in flight BECOMES the final shot if it is still flying (else the next one does; `shotTakeover`), then a handoff to Welcome, which draws the same `LaunchArt` underneath. A signed-in member's Home (`[data-app-shell]`) gets the same final shot and then WAITS for Home to finish (`appSettled` in `lib/appSettled.ts`: no visible `.shimmer-line` in the tab on screen), at most `APP_SETTLE_WAIT_MS` (2.5 s) after the shot lands, while `HomeShell` opens the other tabs behind it — Grant, 2026-10-21: "let the full animation play end to end at least once and use that time to preload" (`docs/plans/tab-keep-alive.md`). That reverses the 2026-10-03 cut ("its done loading faster than 1.5s"), which made it leave at hydration and showed Home's skeletons instead: the wait is only worth it while it is buying a finished screen, so don't hold it for anything else. `/legal`, `/design` and the other non-app routes leave AT ONCE. State is `<html data-launch>` (`loading` → `resolving` → `welcome`/`done`, or `lifted`), and the splash UNMOUNTS afterwards. A 10s CSS failsafe runs only while `loading`, plus an 8s hard timeout after hydration. A pre-paint inline script sets `--launch-k` (the 360×740 canvas scale) and `data-theme` before first paint, hence `suppressHydrationWarning` on `<html>`. The splash takes taps while it is up (the page under it is live), a reload skips the final shot, and a landing URL (`lib/landingParams.ts`, canary-pinned to both shells) leaves at once. `HydrationMark` / `data-hydrated` are gone. **A quick return skips it** (`lib/quickReturn.ts`, 2026-11-06): the signed-in app notes on the phone when it was last in use (on opening and going to the background) and the pre-paint script marks `data-launch="lifted"` plus `data-launch-skipped="return"` on a load within 30 minutes, before anything is drawn; sign-out forgets the note. **Home draws last time's week at once** (`lib/homeSnapshot.ts`): session, who is in and the announcement — never money — kept per club and member for a week, shown dimmed with "Updating…" and every action held until the server's week replaces it; a failed refresh shows the error, never the copy. **Real phones' open times** are `app_ready` events (`ms`, `launchMs`, `start`, `platform`), read back as `appReady` in `clubMetrics` and slice0 (`docs/plans/startup-speed.md`).
- **DevPanel**: Add `?dev` to the URL to show a floating control panel for testing UI states (cost visibility, payment reminder, signed-up status, player count). Controls override real API data. Only active when `?dev` is in the URL.
- **Advance form success screen**: after creating a session the form now STAYS on a success screen (green banner + "Share sign-up link" + "Done"), rather than auto-`onBack()`ing after 1.2s. The point is to let the admin share the sign-up link immediately (item 10); they dismiss via "Done". `AdvanceSessionForm` also carries the title/venue/`birdUsages` forward from the current session and offers recent-value chips (via `/api/sessions/locations` + `/api/birds`); the advance route writes `title`/`locationName`/`locationAddress`/`birdUsages` from the POST body.
- **Active tab persists in `sessionStorage`, not the URL**: `HomeShell` writes the active tab to `sessionStorage('badminton_active_tab')` (and mirrors to `localStorage('badminton_last_tab')`) on every switch (never to the URL). `sessionStorage` is the discriminator between an in-app reload (same page session → restores the last tab) and a quit/cold PWA launch (new session → empty → lands on Home). Writing the tab to the URL would defeat this — the iOS PWA restores the last URL on cold start, so it would reopen on the last tab. Mount precedence: explicit `?tab=` deep-link (honored once, then stripped) → restored `sessionStorage` tab → **recent-excursion restore** (see below) → `'home'`. Don't read `sessionStorage` in the `useState` initializer (it runs during SSR/hydration → mismatch) — restore in a post-mount `useEffect`.
- **External-excursion tab bridge** (`lib/excursion.ts`): iOS often EVICTS the PWA while a system surface is open (native share sheet, full-screen receipt image, Quick Look), so returning looks identical to a cold start — `sessionStorage` is gone and the user gets bounced to Home mid-task. Fix: call `markExternalExcursion()` synchronously right before any such hand-off (`navigator.share`, download-anchor `.click()`); it timestamps `localStorage` (survives the relaunch). On a cold start `HomeShell` calls `consumeRecentExcursion()` (one-shot, 3-min window) and, if recent, restores `badminton_last_tab` instead of Home. A genuine quit-and-reopen sets no marker → still Home. Marked at: `ReceiptSheet` share+download, `AdvanceSessionForm` sign-up-link share. Any new `navigator.share`/file-open must mark too.
- **Tabs are KEPT, not rebuilt** (`docs/plans/tab-keep-alive.md`, 2026-10-21; Grant: "it still has a lot of loading stats everytime i tap on a new page"). `HomeShell` keeps each visited tab mounted under `hidden` and opens the other three behind the launch screen once the first screen has settled (`appSettled`; skipped under the browser's save-data), so a tab switch reads nothing. Admin is kept once VISITED but never opened early (`KEPT_ON_VISIT`; an admin's Admin CODE is fetched in the background and the loaded module is rendered DIRECTLY — through `dynamic()` alone the first tap still suspended and React held its fallback ~300 ms; and `AdminTab` takes `knownAuthed` from the shell's own `GET /api/admin`, so the console does not wait on a second check, 2026-10-25), and inside it the console stays mounted, hidden, under each admin page, so Back shows it at once and re-reads quietly (`AdminDashboard`, Grant 2026-10-25: "Admin is still choppy and slow"). **Mounted no longer means on screen**, so read `useTabActive()` (`lib/tabActivity.ts`, `true` outside a tab) wherever that matters: `BottomSheet` stays shut while its tab is away (it portals out of the hidden panel); a one-shot arrival marker is consumed on ARRIVAL (`[onScreen]` in the effect's deps, as the stringing intent and the Profile sub-screen are); a "this screen was opened" beacon fires per visit (`stats_open`). Data others can change re-checks quietly on return through `useTabReturn` (away ≥ `RETURN_REFRESH_MS`, 10 s; the content stays while it does — Home's week, the balance, the player's rackets, the bench). Each tab keeps its own scroll position.
- **Pull-to-refresh**: `components/PullToRefresh.tsx` (mounted in `HomeShell`) refetches the tab ON SCREEN by bumping its own `tabNonce` entry, folded into that tab's React key — the kept tabs behind it are left alone (`refreshNonce` remounts every tab, and is for a group switch or join) (remount → re-run fetches; no fetch-intercepting service worker — the push worker has no `fetch` handler, so it can't serve a cached response here). Touch listeners live on `document` (body is the scroller); the gesture is disabled while a BottomSheet is open (`body { position: fixed }`). Trigger tuning to avoid accidental fires when scrolling up at the top: a `DEAD_ZONE` (raw drag ignored before any pull registers), a higher `THRESHOLD`, and `disqualified` — any upward travel (`dy < -UP_CANCEL`) marks the whole gesture a scroll so it can't flip into a refresh even if the finger bounces back down past the top edge.
