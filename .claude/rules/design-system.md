# Design System

<!-- Moved word for word from the root CLAUDE.md "Design System" section on 2026-11-08 (it was over the 150k-character limit). The root keeps the always-follow rules; this file loads when Claude touches a matching path. -->

Canonical bundle mirrored at `docs/design-system/` (43 files — tokens, 28 specimen HTMLs, UI-kit JSX refs, self-hosted fonts). `app/globals.css` is the **single source of truth** for tokens in the running app; the docs folder is pristine reference only (never imported).

- **Fonts**: Space Grotesk (display — h1/h2/h3, wordmark, splash) + IBM Plex Sans (body — `var(--font-sans)`) + JetBrains Mono (data — `var(--font-mono)`). Self-hosted subset **WOFF2** files in `app/fonts/`, all three loaded via `next/font/local`. Italic variant wired for IBM Plex. Regenerate with `docs/subset-fonts.md`.
  - **Never add a `next/font/google` import.** It fetches at BUILD time, so an unreachable `fonts.googleapis.com` fails `next build` and the deploy, and it serves from our own origin anyway, which `next/font/local` does without the round trip. `__tests__/design-canary.test.ts` fails the build on one.
- **Icons**: `.material-icons` is Material Symbols Rounded, **self-hosted** since 2026-09-15 — `app/fonts/MaterialSymbolsRounded-Subset.woff2` (98 glyphs, 12.0 KB), built from `lib/iconNames.ts` by `node scripts/fetch-icon-font.mjs` and loaded with `next/font/local` like the other three faces. It was the last render-blocking third-party request on first paint (two hops: googleapis for the CSS, gstatic for the woff2), which is the same reason the body fonts were self-hosted. **A new glyph is TWO steps**: add the name to `lib/iconNames.ts`, then run the script — `__tests__/icon-font-manifest.test.ts` fails with that command when the list and the built font disagree, because a name in the list that is not in the FONT renders as its own word (`expand_less`) at runtime. `display: 'block'` for that reason too: these glyphs are ligatures, so a fallback face paints the word. Icon glyph sizes use the `.icon-xs/sm/md/lg/xl` ladder (13/16/18/24/40px) — mirrored as `--icon-*` tokens for inline `.material-icons` styles (the icon analogue of `--fs-*`; added in the design-audit remediation). Don't hand-type an icon `fontSize` — snap to the nearest rung.
- **Backgrounds** live on the `.court-bg` element (rendered once in root layout). `02 Aurora` (3 blobs with transform-only animation) is the default; `03 Court` (real badminton-doubles proportions, aspect-locked via `aspect-ratio: 100/220` + `background-size: contain`) activates on the Stringing tab via `html[data-tab="stringing"]` selectors (it belonged to Sign-Ups until that tab left the nav on 2026-09-16; the rules were retargeted, not deleted). **Since the fields shipped** (2026-08-26; flag `NEXT_PUBLIC_FLAG_VISUAL_FIELDS` retired 2026-09-10, so this is unconditional) each tab gets a coloured radial-gradient ground instead of the shared aurora — Home green, Stringing amber (inherited from Sign-Ups, the tab it replaced), Stats blue, Profile violet, Admin orange — and **sheets inherit their tab's field** (`.bottom-sheet` reads `data-tab` because BottomSheet portals to `body`, still inside `<html>`). Critically the field goes on `background` while the court SVG / dot grid stay on `::before`, so a field slots *under* a motif rather than replacing it. The flag used to be read server-side and stamped as `html[data-visual="field"]` in `app/layout.tsx`; with it retired, the field rules carry **`html:root`** instead. **That prefix is LOAD-BEARING SPECIFICITY, not a vestige** — it preserves the original (0,2,1), which the field rules need to outrank both a Tailwind utility (0,1,0) and the per-tab `.glass-card` rule at (0,2,1). Unscoping to a bare class silently reverts Stats cards to the pre-field material and re-exposes ~124 call sites to their own `p-*`; jsdom computes every length as `0px`, so no test can see it. `design-canary` pins `html:root .glass-card` for exactly this reason. Home is the un-attributed default, which is also what gives `/design/*` a correct ground.
- **Preview route** at `/bpm/design` (7 sub-pages, flag-gated behind `NEXT_PUBLIC_FLAG_DESIGN_PREVIEW`). Not linked from BottomNav.
- **Corner radii ladder** — rectangular surfaces capped at **16px**. 6/8/10/12/16 for rect; 100px for pill. Glass-card was at 24px historically (self-inflicted spec violation); now 16. **One scoped exception:** `--radius-3xl` (30px) for **field cards only** (`html:root .glass-card`). It is not a new cap — flat-field surfaces still stop at 16. The difference from the old 24px is that 24 was drift and 30 is the radius the field-card material was designed at. Never hardcode `border-radius: 30px`; go through the token. `__tests__/design-canary.test.ts` enforces that, because nothing else can: the ESLint radius rule matches a raw number in a JSX `borderRadius` prop, so `'var(--radius-3xl)'` never trips it, and ESLint does not parse CSS at all.
- **Everything scales by ONE factor, `--ui-scale`** (`docs/plans/ui-scale.md`, 2026-11-12; Grant: "no zoom, card should scale", by text size AND screen). Pinch-to-zoom stays OFF. The ladders (`--fs-*`, `--space-*`, `--radius-*`, `--icon-*`) are rem, written `calc(Nrem / 16)` so the designed px still reads (the canaries read it back as N px), and `html { font-size: calc(100% * var(--ui-scale, 1)) }`, so a card grows whole: text, padding, radius and icons together. The factor is set before first paint by `lib/uiScale.ts`'s script in `app/layout.tsx` — the iPhone's Dynamic Type (`-apple-system-body` ÷ 17, 1–1.5) times the page width (1 up to 480 px, 1.12 at 768; one PAGE on a foldable) — and is **exactly 1 on every phone at the default text size**, so phones are pixel-identical (checked by before/after shots). Android needs nothing added: its WebView already scales the root. **A new size goes through a token or rem**, never a px font-size inside a card: `__tests__/ui-scale.test.ts` lists the px font-sizes kept on purpose (the tab bar, the top bar and its toggles, the launch screen, the courtside scoreboard, an SVG label, the admin tiles) and fails on any other. A component that takes a size in px (`MemberAvatar`'s `size`) draws it as `size / 16` rem. Fields are `max(16px, 1rem)` on a coarse pointer, never under the 16 px that stops iOS zooming on focus.
- **Type-size scale** — `--fs-2xs`(10)/`-xs`(11)/`-sm`(12)/`-base`(13)/`-md`(14)/`-lg`(16) + line-heights `--lh-tight/snug/normal`, with matching size-only `.fs-*` utility classes. Roles: 2xs=section labels/micro badges, xs=tile labels, sm=card subtitle, base=body/hints, md=emphasis, lg=stat values. Plus `--fs-stat`(20)/`--fs-stat-lg`(22) for the Stats tab's headline data numbers (Level, Overall, streak — no Home equivalent). Headlines keep `.bpm-h1/h2/h3`. Use the token/class — never a raw inline `fontSize` number. Named `--fs-*` to avoid clashing with the `--text-*` *color* tokens. (Added in the standardization program, Phase 0; `--fs-stat` + the exact-size sweep in the design-audit remediation.)
- **Inline spacing scale** (rebuilt by the spacing audit, 2026-08-27) — **eleven rungs, and a call site never types a number.** `--space-hair`(1) / `--space-05`(2) / `--space-1..6` = 4/6/8/12/16/20 / `--space-7..9` = 24/32/48. Class-based layout still prefers Tailwind `p-*`/`gap-*`.
  - **`--space-hair` and `--space-05` are OPTICAL, not layout.** They are the 1–2px that baseline-aligns a subtitle under a heading or an icon against its label (`CardHeader`'s docstring has used `marginTop: 2` since it was written). `--space-1` is the smallest *layout* rung — don't reach below it to tighten a real gap.
  - **`--space-7/8/9` are SECTION rungs**, not the micro scale extended. They exist because empty states and sheet safe-areas were typing 24/32/48 with nothing to reach for.
  - **A token may sit off the ladder; a literal may not.** `--home-stack-gap` is 10px because the Home hierarchy pass meant it. That is a named decision. `gap: 10` at a call site was not.
  - **The snap rule**, if you ever need to place an off-rung value: vertical padding and every gap collapse 10 and 14 onto **12**; horizontal padding rounds 14 **up to 16**, because horizontal padding is what separates text from a border and every on-spec control already carries more of it than vertical (`.btn-primary` 12/20, `.btn-ghost` 12/16, `.pill-admin` 4/12).
  - **A pill's padding steps with its text**: `--fs-2xs` → 4/8, `--fs-xs` → 4/12, `--fs-sm`+ → 6/12. Spec lives in `StatusBadge`'s docstring. Before the audit `--fs-2xs` pills alone were drawn at four different paddings, three of them inside `StatusBadge` itself.
  - **A centred fallback** — the message standing where a list would be — is **48/24** at page level (`var(--space-9) var(--space-7)`, or `py-12 px-6`). An empty message *inside* a card takes the card's own 20px instead; it is card content, not a page.
  - **Two guardrails, and you need both.** `__tests__/spacing-canary.test.ts` is the hard gate: it fails the build on any hand-typed value, and it is the only thing that can see the string form (`padding: '12px 16px'`). ESLint's selector reaches numeric literals only. The canary also pins `/bpm/design/tokens` against `globals.css` — that page had been documenting `--space-3` as 12px when it is 8px, five of six rows off by a rung, which is a fair share of where the drift came from.
  - **`space-y-*` is silently defeated by a child's inline `margin: '0'`.** The utility compiles to `> * + * { margin-top }`, and an inline style beats a class selector — so a card that declares the rhythm can have its own children cancel it. `WhereYouSitCard`'s footnote sat **0px** under the bands this way. Use `flex flex-col gap-*` when children carry inline margins; a flex gap cannot be overridden. `card-spacing-canary` cannot see this: it checks the className declares `space-y-*`, and these cards do. **All eleven other candidates were audited (2026-09-02) and ten were false alarms.** Only `KudosReceivedCard` was really broken, and it is fixed. Grep finds far more than exist, for two reasons worth knowing before you trust the next scan: the `margin: '0'` is usually on the **first** child, where `space-y` never applies a margin anyway (`SkillTrendCard`, `CheckInSheet`), or it sits **inside a nested container** that has its own `gap` and is not a direct child at all (`StatsPrivacyScreen`, `StatsSignedOut`, `LearnRegister`, `CommandCenter`, `BirdsPage`). The bug needs a non-first DIRECT child — read the structure, don't count matches.
  - **Peer cards in a rail share a baseline** via `--card-header-row-h` (26px). A card whose header carries a badge is taller than its neighbour's bare label, so their body copy starts at different heights — the Gear rail was 13px out of line. A rail header is a fixed box sized to the tallest thing it can hold, not to its content.
  - **Sanctioned exemptions** (all annotated at their call site): `BpmWordmark`'s `em` values (the ornament scales with its font size), `.badge-ai::before`'s 1.25px (the padding draws a gradient hairline), `.icon-pin`'s 1px glyph nudge, bottom-nav clearance on fixed bars, and **`app/opengraph-image.tsx`** — Satori does not resolve CSS custom properties, so a token there silently evaluates to nothing and raw pixels are correct.
- **A tab's one main action is `.btn-primary`**: filled, full width, a leading glyph, the label centred — Home's "Sign up for this week" and Stringing's "Submit a request" (Grant, 2026-11-11, "button needs to follow pattern"). Not a tinted `cc-btn-primary` with a trailing arrow. One per screen.
- **Button family** — prefer the `cc-btn` family (`cc-btn-primary` / `-secondary` / `-ghost` / `-danger`) for command-center actions. Compose with size modifier `cc-btn-lg` for prominent hero CTAs. The legacy `.btn-primary` (gradient, larger weight) is kept for back-compat but new admin code should use `cc-btn` for the focus ring + a11y. All defined in `app/globals.css`.
- **Foldables get two panes; one screen gets exactly what it had** (`docs/plans/foldable-layout.md`). The last two `@media` blocks in `globals.css` lay out the two panes and stay LAST, because they move rules defined earlier. **Nothing but the page background and a bottom tab bar crosses the centre — never a banner** (Grant: "NEVER"). Nothing outside those blocks may change a single screen: side padding is `--shell-pad-x`. The rest (where the fold is, the courtside scoreboard, the fold motion) is `.claude/rules/foldables.md`, which loads with those files; `__tests__/foldable-layout-canary.test.ts` pins it.
- **Keyboard focus and tap size** (audit, 2026-11-05): `globals.css` opens with ONE default `:focus-visible` ring (2px accent, 2px offset) under `:where(...)`, so it carries the bare pseudo-class's specificity and every control's own focus rule still wins — before it, anything without a rule got the browser's ring, which Safari draws dark blue on the dark glass. A control drawn under 44px takes a 44×44 tap through an inset `::before` rather than growing (the three top toggles, the toast's ✕), or a 44px-tall `::after` overlay — the list in `globals.css` under "44pt tap targets" (the register switch's tabs, Home's "Add to calendar", Stats' small actions) and `.tap-44` for a control with no class of its own; never on a box that clips its overflow (put a `line-clamp` on an inner span), and `__tests__/tap-target-canary.test.ts` pins it (the Apple pass, 2026-11-12). Dark `--text-muted` is 0.62 white, which is AA (4.5:1) on every field's lit corner where 0.55 read 3.9:1.
- **Stat tiles** — `.cc-tile` with severity variant (`warn` / `bad` / `info`) is interactive (cursor:pointer, hover). Use `.cc-tile-static` for read-only stat displays so you don't render three buttons that all go to the same place.
- **Containers are FILL-ONLY — no outer stroke** (Grant, 2026-11-04: "no outer stroke border on most UIs", Home as the reference; the Stringing bench took the same call on 2026-10-28 at `.cc-mini-card`). A card, a tile, an option row or a callout is a tint on the surface, never a tint with a rim, and a SELECTED one is a solid tint with accent text — the Level pill's own treatment — never a border or a ring. Keep `border: 1px solid transparent` rather than `none` so the box keeps its size. Between groups inside a card, space alone separates (the "no hard divider lines" rule), never a hairline. The Fit page, the rest of the Equipment register (the Set-up card's lines, its line sheet's actions and feel chips, the tension stepper and ruler, the racket page's tiles, spec grid, accordion rows and chart track) and Play's kudos notes were brought in line the same day. **The one rim that stays is a label chip that is not a control** — Home's "Focus drill · Your record · Racket fit" row (Grant: "keep home chips"); a pressable choice chip is a control and is fill-only like a tile. The admin console followed the same day (Grant: "do the admin console ones too"): `.cc-tile`, `.cc-mini-card`, `.cc-session-chip`, `.cc-choice`, the filter and shelf chips and the catalog-gaps rows are fills. **The one rim left on purpose is `.admin-hero`'s green edge**, which its rule says is the "you are in admin" marker; the button family (`.cc-btn-*`, outlined by design) and the status pills (labels) are not containers and keep theirs. `DESIGN.md` §9 and §12 say the same.
- **A way out is a quiet link, not a button** — `.link-quiet` (underlined secondary text, 44px tall; `.link-quiet--flush` drops its side padding) for "Forgot PIN", "Use email instead", "Back to…". Never a `.btn-ghost` pill: a stack of equal pills makes the escape hatch look as important as the action.
- **Filters are one sideways-scrolling row** — `.filter-chip` inside `.filter-chips`; an applied filter is `.filter-chip--applied` (green fill, remove glyph). Fill-only, never a second row.
- **Design system first — always**: Use established patterns from `globals.css` for all interactive element states. When no explicit rule exists for a new case, derive from the nearest existing principle rather than inventing ad-hoc values. Example: a list row that will be tappable in a future sub-issue uses `opacity: 0.5; pointer-events: none` — same principle as `.cc-btn:disabled`. If a genuinely new pattern is needed, name the principle and define it in `globals.css` before using it inline.
- **Composition primitives** (`components/primitives/`, from the standardization program): prefer these over hand-rolling the layout — they bake in the canonical spec so it can't drift.
  - `<CardHeader icon title subtitle? badge? action? />` — the icon + `bpm-h3` title (+ `--fs-sm` subtitle) (+ trailing badge/action) row atop a `.glass-card`. Two-tier spec: icon 22/accent, `flex-start` + icon `marginTop:1` when a subtitle is present.
  - `<StatusBadge variant="accent|muted|phase|state" tone? >` — the uppercase pill (Live/Beta = `accent`, compact "Coming soon" = `muted`, skill-phase = `phase` with `tone="amber"` for switch, and since 2026-10-10 `state` with `tone="paid|unpaid|waitlist|admin"`, which wears the canonical `.pill-*` class so a FILLED status chip — the bench's job status — takes its shape, padding and colour from CSS). Don't hand-code pill spans: the bench's was drawn at a `--fs-sm` padding on `--fs-2xs` text.
  - `<ErrorState message action? />` / `<EmptyState>` — the legible-fail surfaces. ErrorState is always `role="alert"`: WITH an `action` ("Try again") it is the standing icon-over-text state, `cloud_off` over the message in neutral ink (`.error-state`), the same layout as a standing EmptyState; without one it is the inline red `.field-error` line. **A load failure is not red** (Grant, 2026-11-11: the server did not answer, the person did nothing wrong); red is for what the person must fix (a wrong PIN, a form error, a refused sign-up). EmptyState is muted "no data yet" body copy. Keep them distinct by their words and glyph (a loaded-empty card must not read as a failure).
  - `<ListRow leading? title subtitle? trailing? onClick? />` — structural row layout (renders a `cc-mini-card` button when `onClick` is set). Not opinionated about text styling; slots take nodes.
  - `<MoneyInput value onChange />` — a typed dollar amount, the `$` drawn INSIDE the field in the data face. The stringing screens had three ways to say dollars (inside, beside, and "($)" in the label); there is one now. String-valued: the caller parses, because an empty field is usually an answer ("Ask", "not priced yet"), never zero.
  - The `<BottomSheet>` primitive (below) predates these and is the same idea for sheets.
- **Inner-content reference** (the single "one true reference" for in-card content styling, derived from Home/Sign-Up and codified 2026-06-18): use these roles instead of hand-rolling raw Tailwind (`text-xl`/`text-sm`) or raw px. Stats/admin cards already conform via the primitives.
  - **Card container**: `.glass-card` (16px radius). Content cards pad **20px** (`p-5`); compact tiles (date/location) pad **16px** (`p-4`).
  - **Card title**: standard card-header title = `.bpm-h3` (18px) via `<CardHeader>`. The bare hero heading (Sign-Up's "I'm in this week") = `.bpm-h2` (20px) — use the same class in every state (don't fork into `text-xl font-bold text-green-400`).
  - **Card subtitle**: `--fs-sm` (12px) via `<CardHeader subtitle>`.
  - **Primary body copy** (announcement, AI insight, the card's main reading payload) = `--fs-md` (14px), `--text-primary`. **Muted/secondary** helper lines = 12px, `--text-muted`. (13px `--fs-base` is the generic body token but Home renders primary body at 14 — match it.)
  - **Section label** (uppercase eyebrow) = `--fs-2xs` (10px) / `.section-label` (11px), 700 display.
  - **Inner rows + stat tiles** (`ListRow`/`cc-mini-card`/`cc-tile` inside a card): **12px radius (`--radius-lg`) + 12px padding**. `.cc-tile` itself is 12px now — the spacing audit fixed the shared class rather than leaving every call site to override it. Don't override it per use; that double-tightens.
  - **Inline stat/value numbers** = `--fs-md` (14px). The Stats tab's headline data numbers (Level, Overall, streak count) are a deliberate larger mono scale (20–22px) — Stats-specific, no Home equivalent.
- **Token guardrail (ESLint)**: `eslint.config.mjs` steers inline styles toward tokens via two selector sets. `DESIGN_TOKEN_SELECTORS` flags bare hex color literals + raw inline `borderRadius` numbers. `EXTRA_TOKEN_SELECTORS` (added in the design-audit remediation) flags numeric `fontSize` properties, bare `rgba()` literals, and bare Tailwind text-size classes (`text-xs/sm/base` — space/edge-delimited so `md:text-sm` and `text-gray-300` aren't matched; migrate to `.fs-sm/md/lg`). The `var(--accent, #22c55e)` fallback form is fine (hex is inside the `var()` string). `SPACING_TOKEN_SELECTORS` (spacing audit) flags numeric `padding`/`margin`/`gap` properties, skipping `0`. All three sets are folded into the SAME `no-restricted-syntax` entries — flat config merges by rule KEY, so a second config block naming that rule for the same files *replaces* the first: adding spacing as its own block silently switched the colour and radius guardrails off and the warning count fell 363 → 45 with nothing looking broken. App-wide the sets are `warn`; **per fully-cleared area they tighten to `error`** — `components/stats` errors on `DESIGN_TOKEN_SELECTORS`, and `components/{primitives,home,BottomSheet}` plus the stringing service on both sides (`components/stringing`, `StringingTab`, `DatePicker` and the bench's `Stringing*` / `String{Shelf,Purchase}*` / `HoleCountsCard` / `OtherPricesCard`, since the 2026-10-22 design review) error on the **full** set (zero drift). Add areas to the error override as each reaches zero drift. There are currently **12** files carrying a `no-restricted-syntax` escape hatch in the app (`lib/setupShareCanvas.ts` and `lib/invitePoster.ts`'s canvas palettes, `lib/racketCustom.ts`, `lib/racketLook.ts` (racket paint, and the two avatar grounds since 2026-11-05) and `lib/racketLivery.ts`'s racket paint, `lib/racketModel.ts`'s bump-map greys, `lib/stringPacks.ts`'s packet paint and `lib/stringPack.ts`'s drawing, `lib/stringShelf.ts`'s string type tints and maker's colours, `components/auth/GoogleMark.tsx`'s brand hex, `app/design/tokens/page.tsx`, `app/global-error.tsx`), each annotated at the site; the docs canary pins that count EXACTLY, because this sentence said **zero** for weeks after recharts left and nobody noticed. (The recharts SVG stroke/fill attributes were the original ones and left with it in Stage 8.) If you genuinely need one, carry an `// eslint-disable-next-line no-restricted-syntax` with a stated reason. The `design-canary` test (`__tests__/design-canary.test.ts`) pins the token/class contract.
- **Compat & semantic tokens (design-audit)**: the audit defined 10 previously-*undefined* "phantom" tokens that call sites referenced via `var()` (silently falling back to non-theme-aware hex): `--color-red`, `--color-amber`, `--text`, `--border`, `--border-subtle`, `--sev-warn`, `--bg-surface`, `--bg-elevated`, `--ease-out-quart`, and `--font-mono` (the last was a live defect — ~47 bare `var(--font-mono)` sites were inheriting the sans body font, so mono/data numbers lost JetBrains Mono). All now have `:root` + `[data-theme=light]` values. **Palette color classes are theme-aware via `[data-theme=light]` overrides (DESIGN.md §8), not tokens** — keep that convention; add a light override for any new `text-*-NNN` you use rather than converting to a token. The `.field-error` class is the single home for the sanctioned inline error message (`role="alert"`, `--sev-crit-text`, `--fs-sm`) — use it instead of hand-writing `text-red-400 text-xs`; its amber twin `.field-warn` (`--sev-warn`) is the home for a refusal that is not the person's fault (try again later, account exists, invite only). Never an inline `color`/`fontSize` on a `role="alert"` line. **Item #6 of the audit (migrating legacy `btn-primary`/`btn-ghost` → `cc-btn`, and `<CardHeader>`/`<ListRow>` adoption) is deliberately NOT done** — `.btn-primary` (prominent filled CTA) and `.cc-btn` (compact admin action) are distinct visual roles, so it's per-component design work, not a mechanical sweep. See `docs/plans/design-audit-remediation.md`.

## Gotchas

<!-- Moved word for word from the root CLAUDE.md "Gotchas" on 2026-11-09, to keep the always-loaded file short. -->

- **DatePicker is custom**: Portal-rendered to escape `backdrop-filter` stacking. Don't replace with native. **It opens ABOVE its field when the calendar would run off the bottom of the screen** (`placeCalendar`, measured on open): inside a bottom sheet the page is locked, so a field low in the sheet left its calendar's last weeks unreachable. Its trigger is `.date-picker-trigger` in `globals.css`, which mirrors the input rules (radius, border, flattening inside a `.glass-card`); its 42px height is the date/time control height, so it lines up with a native time field beside it.
- **Containing-block trap with `position: fixed`**: a parent with `transform`, `filter`, or `perspective` (e.g., `animate-slideInRight`) becomes the containing block, and `position: fixed` resolves against IT instead of the viewport. Result: "fixed" elements scroll with the page. Fix: portal out via `createPortal` to `document.body`. RosterPage's FAB hit this.
- **No charting library**: `recharts` was uninstalled in Stage 8 with its only consumer (`SkillsRadar`). Stats draws `DimensionBars` and the trend as inline SVG, which is also why those files can use `var()` tokens — recharts wrote stroke/fill as SVG *attributes*, where `var()` doesn't resolve, and that was the reason for most of the token-guardrail escape hatches. Don't reach for a chart library without checking whether inline SVG covers it.
- **Bottom sheet primitive**: Use `<BottomSheet>` from `components/BottomSheet/` for any new sheet/drawer. It handles portal mount, body scroll lock, focus trap (and `aria-modal`, so a screen reader stops at the sheet too — 2026-11-05), Escape-to-close, **drag-to-dismiss** (since 2026-09-16: a grabber, plus the grabber and `BottomSheetHeader` as grab surfaces — never the body, which is the scroller; a quarter of the sheet's height or a flick dismisses, anything less springs back; a `closeOnEscape={false}` sheet gets neither grabber nor drag), and CSS-driven animation (180ms ease-out-quart). Inline `zIndex: 60` (sheet only — no backdrop, no backdrop-tap dismiss). **Every sheet is ONE size** (2026-09-14): `.bottom-sheet` in `globals.css` reads `--sheet-max-w` (32rem) and `--sheet-max-h` (88dvh), and height follows content up to that cap. There are no `width` / `maxHeight` props any more — they had grown three widths and nine height caps — and `__tests__/sheet-size-canary.test.ts` fails the build on a size set at a call site, including one smuggled in through `className`. **56 consumers** (2026-10-10; the docs canary pins this within 25%) — find the live list with `grep -rl '<BottomSheet' components app`, never trust a written one. DatePicker is NOT a bottom sheet (popover anchored to an input).
- **A sheet's main action is pinned to the bottom of the screen** (Grant, 2026-11-11, on the canvas: "For all CTA that show up on an action sheet, … make it anchored to the bottom of the screen"). The button that finishes the sheet — Save, Send, Next, Done, a Keep / Delete pair — goes in `<BottomSheetFooter>`, a SIBLING after `<BottomSheetBody>`, so it stays in reach while the content scrolls; an error about that action sits in the footer just above it. A sheet whose body is a `<form>` keeps the form in the body and gives the footer's submit button `form={id}` (`useId`), so Enter in a field still submits. What stays in the body: an action that belongs to ONE row, a secondary link, and a menu sheet whose every row is its own action. `__tests__/sheet-footer-canary.test.ts` fails the build on a sheet with a primary button and no footer unless the file is on its exemption list with the reason. Stringing moved first (#871), the rest of the app on 2026-11-12.
- **Sheet body lock**: Use `position: fixed` on `<body>` (handled inside `useBodyScrollLock`). Plain `overflow: hidden` doesn't stop iOS rubber-band / pull-to-refresh. The `<BottomSheet>` primitive applies this automatically while open.
- **Per-tab backgrounds**: `HomeShell` writes `document.documentElement.setAttribute('data-tab', activeTab)` via a `useEffect` on every tab change. CSS rules under `html[data-tab="..."]` swap the background per tab. **The pre-fields state was already three overrides, not one** — Sign-Ups `03 Court` (now the Stringing tab's), Stats `05 Tempo Field` (42px dot grid + a tab-scoped `.glass-card` override at blur 22 / saturate 220%), Admin flat `--page-bg`; only Home and Profile fell through to the aurora. With the fields on, all five tabs have a ground. Add future variants via the same mechanism — no component changes needed.
- **Design-system cascade trap**: Do NOT import `docs/design-system/colors_and_type.css` anywhere in the app. Its `:root` block re-asserts dark-mode tokens and shadows `app/globals.css`'s `[data-theme="light"]` overrides (same specificity, later-wins). `globals.css` is the single source of truth for tokens; the docs file is the pristine bundle reference only.
- **`ReceiptSheet` group preview uses a callback ref**: the canvas is drawn from a `ref` callback (`drawCanvas`) the instant it mounts, then exported to a PNG shown via `<img>` (with a sized placeholder until ready). A passive effect reading `canvasRef.current` raced the ref attach and left the preview a blank void — don't revert to that.
