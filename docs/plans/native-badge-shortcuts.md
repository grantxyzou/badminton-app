# Native: the icon badge and long-press shortcuts

**Track:** the native shell (`docs/plans/native-shell.md`), its first additions after launch.
**Status:** in-flight
**Review on:** 2026-12-01 — after a month on the store build that carries this: does anyone use a shortcut, and has the badge been called annoying?

## Problem

Grant, 2026-10-21, after the store app went live: "Can we have widgets with
this pwa version or now we are in App Store what other feature can we look in
into". On the Native canvas page he chose two of the four boards to build
first: "Add icon and long press to native app" — the red count on the app
icon, and the menu a long press on it opens.

## Kill criterion

If a month after the build ships nobody has opened the app from a shortcut
(the beacon is the `tab_view` that follows a cold start with no tab
restored), the shortcuts come out of the next build rather than staying as a
menu nobody reads. If the badge is called nagging, it goes before anything
else does: it is the one piece that sits on someone's home screen uninvited.

## Non-goals

- Widgets and the stringing Live Activity (the other two Native boards) — a
  later build, and they need an endpoint of their own.
- A badge for anything but money owed.
- Asking for notification permission to get a badge. The badge rides on the
  permission push already asked for; without it there is simply no badge.

## Decisions

- **2026-10-21 — the badge counts what is owed and FROZEN**: settled session
  lines the member has not said they paid, plus billable stringing charges.
  This week's session is not counted before its bill goes out — a red 1 for a
  night not yet played reads as a debt that does not exist yet. The count
  comes from the data Home's balance card already reads
  (`GET /api/players/unpaid`), never a second request.
- **A failed or refused read leaves the badge alone.** Unknown is not zero:
  clearing on an error would tell someone who owes that they do not.
- **Clearing to zero happens only on a change.** On iOS a zero badge also
  clears BPM's delivered notifications, so the badge is set to 0 only when it
  was above 0 — the moment the last line is paid — and never on every open.
- **Shortcuts: Sign up for this week, What I owe, Request stringing.** The
  canvas board's three, with the live line under each (the session's date, the
  amount owed). Home holds both answers already; the shortcut list is rebuilt
  from them when they change. "Request stringing" opens the request form, not
  just the tab.
- **Signing out clears both**, before the identity goes — a shared phone must
  not keep the last person's balance on its icon.
- **The plugins are capawesome's Badge and App Shortcuts (v8).** Both are
  `@capacitor/core >=8`, both hold a shortcut tap that launched the app until
  the web app's listener attaches. iOS needs `SceneDelegate.swift` to forward
  the tap; that hand edit is pinned by `__tests__/native-shell-projects.test.ts`.
- **Version skew is normal here**: the web app on a phone is always newer than
  the binary. Every call asks `hasNativePlugin()` first and does nothing on an
  explicit `false`, so the deploy that ships this code is harmless on the
  store build that predates the plugins.
